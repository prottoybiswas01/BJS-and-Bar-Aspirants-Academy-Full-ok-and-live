# COMMAND 05 — Student data ownership, privacy and IDOR audit

## Scope and method

The audit used local source and Git history on `security/phase-01-hardening`. The baseline was `53309f4` (RBAC), following `038742f` (Firebase) and `54a0826` (authentication). The working tree was clean before the change. Route declarations, aliases, authorization helpers, model queries, DTOs, browser state and data-sharing services were reviewed. The report contains code references and synthetic test evidence. No production service, account, data store or provider was queried.

### Findings and treatment

| Severity | Verified code evidence | Impact | Treatment |
| --- | --- | --- | --- |
| High | `53309f4:server/server.js:1206–1207, 1289` | Public signup returned Student hashes and a raw Mentor record created with a plaintext password. | Project acknowledgments, save pending Student data in one transaction, and hash new Mentor credentials. |
| High | `53309f4:server/server.js:5246` | Draft flags were unavailable on the dashboard read and its fallback could serve deleted lessons. | Load current lessons and publication flags, then enforce current scope. |
| High | `53309f4:server/server.js:2937` and shared course access | Historical membership could admit an unrelated Student to a Mentor roster. Ambiguous aliases could match multiple courses. | Apply authoritative membership precedence and only unambiguous aliases. Omit other course IDs. |
| High | `53309f4:server/server.js:8763, 7043, 7456, 7492` | Stale snapshots could supply a receipt, exam result or certificate after removal or revocation. | Require live records with verified ownership, including before PDF render. |
| High | `53309f4:server/server.js:7101` and `getExamLeaderboard` | Public standings linked names and a phone field to grades. | Use anonymous public and peer labels. Retain names for authorized Admins. |
| Medium | `53309f4:server/server.js:7527` | An existing push endpoint could be reassigned via a different Student session. | Bind the upsert to the owner and enforce endpoint uniqueness. |
| Medium | `53309f4:server/server.js:5943, 7987` | Staff responses could contain credential and profile fields beyond their operational purpose. | Use explicit staff response fields, bounded pagination and live directory records. |
| Medium | `53309f4:server/server.js:7916` and `requireStudentSelf` | Target validation handled only some identity aliases and privileged fields. OTP already constrained contact mutations. | Validate all known selectors, prohibit privilege changes, and keep contact changes bound to a verified challenge. |
| Medium | `53309f4:client/src/context/AuthContext.jsx:28` | Full profiles persisted across browser sessions. Raw HTTP errors could include token headers and student entries. | Restore the verified profile into memory, clear legacy state, and prevent cross-session responses and private caching. |
| Medium | `53309f4:server/server.js:7456` | Public certificate verification exposed extra academic metadata and guessable references. | Minimize public fields, apply a shared rate quota and randomize new references. |
| Low | `53309f4:server/server.js` email dispatch and legal assistant handlers | Normal logs used delivery addresses and the AI prompt assembled a personalized greeting from the authenticated name. | Logs omit direct addresses. The AI request uses a generic salutation. |
