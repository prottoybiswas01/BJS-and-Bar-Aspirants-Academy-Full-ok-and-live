## Rollout and compatibility

- Configure the expected `CRON_SECRET`, `TELEGRAM_WEBHOOK_SECRET`, and `RESEND_WEBHOOK_SECRET` server-side. Re-register Telegram with the verified webhook secret before enabling updates. Resend verification requires the signed raw body and the configured provider client. Keep the COMMAND 02 and COMMAND 03 runtime variables in place. Tests use fixture configuration.
- Staff issue or update payment receipts from the Payment interface. Enrollment approval grants course access without manufacturing a payment or inventing a receipt amount. The data model has receipt issuance, editing and deletion, with no separate payment-rejection record or gateway approval flow in this revision.
- Private receipts, results and certificates follow stored academy IDs. Older records that rely solely on email, phone or an obsolete account ID require an approved ownership review. Public certificate verification and authorized PDF download continue as separate operations.
- Approved Mentors can see their assigned courses and own assignments and grade and report on the submissions for those assignments. The audit found no established cross-Mentor delegation workflow. Adding delegation would require an explicit policy and stored grant.
- `isPublic` on MCQ records continues to allow public testing. Review older course-associated exams that intentionally or historically have this flag enabled. Answer keys stay out of the pre-submission response.
- Self-service profile changes require mailbox proof. Recovery uses one-time, durable challenges and Mongo transactions. Existing JWTs still follow the COMMAND 02 session lifetime. Remove pre-release cache entries that could contain formerly unrestricted responses at rollout.
- Production database safety: the HTTP demo reset and `server/scripts/cleanStudyNotesOnly.js` reject the production database. The old `test_academy_upgrades.js`, `test_e2e_suite.js`, and `test_production_critical_fixes.js` contain destructive calls and were excluded from this validation. Single-resource delete operations remain gated. Exam and assignment deletion can also remove dependent test results or submissions.
- Review the frontend password-change and temporary-password callers that had no matching Express routes at the baseline. Their intended recovery UX requires separate compatibility verification. The existing Admin/Student/Mentor login and the verified password recovery paths remain covered by the isolated tests.
- Stage authorized account fixtures, verify production-equivalent Vercel functions and MongoDB transactions, and smoke-test payments, course enrollment, videos, exercises, certificates, webhooks and approved legacy ownership before rollout. No production records or live operations were used for this audit.
